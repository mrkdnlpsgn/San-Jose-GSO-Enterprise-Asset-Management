The "Audit" Check-Point

At the Business Tier, the system conceptually validates user input before sending it to the Database to prevent errors and corrupt records. When a user submits an equipment form with an empty itemCode or article, the @Valid annotation on the controller's @RequestBody parameter triggers Jakarta Bean Validation against the @NotBlank constraints declared on the entity.

If validation fails, Spring throws a MethodArgumentNotValidException, caught by our GlobalExceptionHandler. It responds with HTTP 400 Bad Request and a JSON payload listing each invalid field. The transaction is never committed, no row is inserted, and the database remains in a consistent state.

As defense-in-depth, the Data Tier also enforces UNIQUE on item_code and NOT NULL on required columns — even if validation were bypassed, MySQL would still reject duplicate or incomplete records. This two-layer integrity model ensures inventory data remains accurate and trustworthy for COA audits.
