A. The Graph

The X-axis represents the number of concurrent users accessing the system simultaneously, while the Y-axis represents the average response time in seconds. The curve shows how the system's single-server setup is predicted to behave as load increases — remaining flat under normal usage, gradually rising in the acceptable zone, then sharply degrading at the break point before reaching failure conditions.

B. The Break Point

The break point is predicted to occur at approximately 150–200 concurrent users. At this point, the database connection pool becomes saturated, JPA's eager-fetching of DeviceRecord collections triggers N+1 query patterns, and the single Spring Boot instance can no longer maintain sub-second response times. Beyond 500 users, the system would reach failure conditions — request timeouts and dropped connections.

C. The Narrative

Based on our target users identified in Chapter 1 — the San Jose Municipal Hall ICT Division staff (~5–10 users), department heads viewing inventory (~10–20 users), and peak audit-period concurrency (~30–50 users) — the system's break point at ~150–200 users sits well above actual demand, providing a comfortable safety margin for normal operations.

However, this prediction directly justifies the scalability strategy planned in Material 1. The stateless JWT authentication design means we can horizontally scale by adding more Spring Boot instances behind a Load Balancer (Nginx) without session affinity issues. The MySQL database can be configured with read replicas for the High Availability strategy — particularly during COA audit periods when reporting queries grow heavy.

With a load balancer distributing traffic across 2–3 application servers, the break point would shift past 1000 concurrent users — more than sufficient if the system is later adopted by other municipalities in Batangas province. The RateLimitingFilter already in place also protects against brute-force attacks that could artificially spike load before legitimate scaling decisions are needed.
