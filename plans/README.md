## Recommended execution order

1. **001, 002** (frontend, HIGH), highest-leverage fixes, independent of everything else. Do these first.
2. **003, 010** (frontend, same file: `Sidebar.jsx`), execute sequentially, not in parallel, to avoid two agents patching the same file at once. Either order is fine; they touch disjoint sections (003: the `aside` width transition; 010: the collapsed tooltip).
3. **004, then 005** (frontend, drawer patterns). Do 004 first. 005 adds an `onExitAnimationEnd` prop to `RecordDrawer.jsx`/`LogDrawer.jsx`; 004 uses those same two files as a **read-only exemplar** to copy the (current, `setTimeout`-based) pattern onto `AssetDrawer.jsx`. If 005 runs first, the exemplar will already look different from what plan 004 documents: 004's executor should still succeed (the copied pattern would just include the `transitionend` improvement too), but running 004 first keeps each plan's diff attributable to itself.
4. **006, 007** (mobile, MEDIUM), independent of each other and of everything above.
5. **008** (frontend, accessibility), independent, low risk.
6. **009, 011, 012** (low-severity, independent files), any order.
7. **013, 014, 015, 016, 017, 018** (mobile, LOW/polish, mostly independent files), any order. Note 018 has a built-in escape hatch (skip if the `Badge` API doesn't cooperate), don't block on it.
8. **021, then 020** (mobile, same file: `staggered_entrance.dart`), **do 021 first.** Plan 020's Target code for this file still shows the pre-021 `25 *` literal (since it was written before 021's bump was decided), if 020 is executed first instead, its executor should adapt to whatever the live literal actually is (`25` or already `40`) rather than treating the mismatch as drift-worth-stopping-over; but doing 021 first avoids the ambiguity entirely.
9. **019** (mobile, wide blast radius). Do this **last**, and in isolation from the same-session app_theme.dart changes in step 8's plan 020 (which adds a `ReducedMotionX` extension to the same file, immediately after the line 019 changes). Execute 020 before 019 if both are in play, since 019's single-line change is trivial to reapply after 020's addition; doing it in the other order risks a stale line-number reference. Feel-check 019 on its own before combining with anything else, since it affects every animated surface in the app simultaneously.
